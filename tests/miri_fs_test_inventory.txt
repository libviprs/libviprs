# Every test in the tree that either touches the filesystem or carries
# `#[cfg_attr(miri, ignore)]`, with its annotation state. Read and enforced by
# `tests/miri_ignore_convention.rs` (issue #652); nothing else consumes it.
#
# Why it exists. `merge-gate.yml` runs `cargo +nightly miri test` as the only
# check this repository has on undefined behaviour, and Miri aborts the whole
# run on the first operation its isolation layer refuses rather than failing
# that one test. So a single new test calling `tempfile::tempdir()` takes the
# gate down and reports as "Miri failed", which sends the reader looking for UB
# that is not there. The convention that avoids it, an
# `#[cfg_attr(miri, ignore)]` on filesystem-touching tests, was enforced by
# nothing at all until this file existed, and it duly broke:
# `src/checksum.rs` grew three tempdir tests without one.
#
# Columns:
#
#   annotated | unannotated    whether the test carries `#[cfg_attr(miri, ignore)]`
#   fs-detected | not-detected whether the scanner found a filesystem call in the
#                              body itself, as opposed to reaching one through a
#                              helper it cannot follow
#   <file>::<test>             repo-relative path and function name
#
# The `unannotated fs-detected` rows used to be a ledger of known debt, 138 of
# them, on the argument that PR #644 disabled Miri's isolation so letting them
# run cost nothing. #711 put isolation back, which made every one of them a way
# to end the whole session on its first syscall, and #712 and #739 annotated
# 134 of the 138.
#
# So this is not a ledger any more.
# `no_filesystem_touching_test_runs_under_miri_outside_the_named_exceptions` in
# `tests/miri_ignore_convention.rs` refuses a filesystem-touching test that is
# neither annotated nor named in `UNANNOTATED_FS_EXCEPTIONS`, and that list is
# the four rows still spelled `unannotated` below. They are all in
# `src/resample.rs`, which had four pull requests open against it while the
# sweep ran, and issue #756 carries them. Nothing else can join them without an
# edit to that constant and a reason that survives review.
#
# The rows stay, and the exact set-equality check with them, because they catch
# a different edit from the refusal: an annotation being *deleted*, and an
# annotation being added to a test the detector cannot see through. A refusal
# alone is green when somebody annotates a pure test by mistake; this file is
# what turns that into a new `annotated not-detected` row and a red build.
#
# The `annotated not-detected` rows are the scanner's blind spot made durable.
# Those tests reach the filesystem through a helper or through a library
# function that opens a path, so the detector reads their bodies as pure. They
# are pinned anyway, which means their annotations cannot be deleted unnoticed
# even though the detector could not have asked for them in the first place.
#
# To update: run `cargo test --test miri_ignore_convention`. The failure prints
# a regenerated body you can paste in below this header. A `+ unannotated` line
# in that output is a test that will end the next Miri run on its first
# syscall, so the answer to it is an annotation, not a paste.
