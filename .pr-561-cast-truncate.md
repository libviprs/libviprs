`Raster::try_cast` rounds a float sample to the nearest integer when it narrows to `Gray8` or `Gray16`. `vips_cast` truncates. `cast.c:566-567` says it in as many words, "Floats are truncated (not rounded). Out of range values are clipped", and the binary agrees, so every fractional sample in the crate's float-to-integer path lands one above vips roughly half the time.

Measured on vips 8.18.4, `csvload` (double) then `cast`:

```sh
printf "1.7\n2.5\n3.999\n254.6\n" > p.csv
vips csvload p.csv p.v && vips cast p.v pu.v uchar
for y in 0 1 2 3; do vips getpoint pu.v 0 $y; done
```

| input | `vips cast` uchar | libviprs today |
|---|---|---|
| `1.7` | 1 | 2 |
| `2.5` | 2 | 3 |
| `3.999` | 3 | 4 |
| `254.6` | 254 | 255 |

This is the tests-only commit, so the divergence is on record before the arithmetic moves. Four pins go in: two for the rounding mode on each unsigned target, and two guarding the neighbouring rules that already match vips and must not move. Clipping passes unchanged in both directions on both targets, and NaN fails only on its non-NaN companion sample, which is what I wanted it to show, since NaN needs its own branch either way (`trunc(NaN)` is `NaN` and `f64::clamp` passes `NaN` straight through to the cast).
